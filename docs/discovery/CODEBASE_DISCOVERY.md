## Entry Points and Bootstrap

- **Confirmed — native to Dart handoff:** Android declares `.MainActivity` as its launcher activity; `MainActivity` extends `FlutterActivity`. The Android `LaunchTheme` displays `@drawable/launch_background` until Flutter draws its first frame. Evidence: `android/app/src/main/AndroidManifest.xml`; `android/app/src/main/kotlin/com/nqm/infinityworld/MainActivity.kt`; `android/app/src/main/res/values/styles.xml`.
- **Confirmed — Dart entry point:** `lib/main.dart` defines `Future<void> main()`. It calls `WidgetsFlutterBinding.ensureInitialized()`, awaits `resolveStartupRoute()`, then starts `ProviderScope(child: MainApp(initialRoute: initialRoute))`. Evidence: `lib/main.dart` `main`.
- **Confirmed — launch decision and session persistence:** `resolveStartupRoute` constructs or receives `LocalSessionRepository`, calls `hasSession()`, and returns `AppRoutes.main` only when a persisted login flag and non-blank display name exist; otherwise it returns `AppRoutes.login`. The repository defaults to `SharedPreferencesAsync`. Evidence: `lib/app/bootstrap/startup_route_resolver.dart` `resolveStartupRoute`; `lib/features/auth/data/local_session_repository.dart` `hasSession` / `getDisplayName`.
- **Confirmed — root application and routing:** `MainApp` is the root `ConsumerWidget`. Its constructor creates a `GoRouter` through `createAppRouter(initialLocation: initialRoute)`, and `build` supplies that router to `MaterialApp.router`. There is no router redirect in the inspected `GoRouter`; startup selection happens before `runApp`. Evidence: `lib/main.dart` `MainApp`; `lib/app/router/app_router.dart` `createAppRouter`.
- **Confirmed — shell initialization:** the `/main` route returns `MainScreen`, a local `StatefulWidget` that switches among its five tab widgets by selected index. It is not a `ShellRoute` or `StatefulShellRoute` implementation. Evidence: `lib/app/router/app_router.dart` route for `AppRoutes.main`; `lib/app/shell/main_screen.dart` `_MainScreenState`.
- **Confirmed — theme initialization:** `MainApp` watches `appThemeModeProvider`, uses `ThemeMode.system` while it is loading or on error, and supplies `AppTheme.light` and `AppTheme.dark` to `MaterialApp.router`. `AppThemeModeController` reads persisted selection through `AppThemeModeRepository` and `SharedPreferencesAsync`; `AppTheme` builds Material 3 themes using `IwColors` and `IwRadius`. Evidence: `lib/main.dart` `MainApp.build`; `lib/app/theme/app_theme_mode_provider.dart`; `lib/app/theme/app_theme.dart`.
- **Confirmed — provider/service setup at startup:** the root `ProviderScope` enables Riverpod. The initial route lookup directly uses the local-session repository before the widget tree; theme persistence is loaded by its watched async provider. `dioProvider` exists as a lazy Riverpod provider, but no H1 evidence shows it being eagerly initialized during startup. Evidence: `lib/main.dart`; `lib/core/network/dio_provider.dart`.
- **Unknown — startup behavior on iOS and non-mobile platforms:** platform folders are present, but H1 did not run those targets or trace their native launch paths. This inventory makes no runtime-compatibility claim for them.

## Current Architecture

- **Confirmed — app composition:** `lib/main.dart` composes Flutter binding initialization, the pre-widget startup decision, root `ProviderScope`, `MainApp`, `MaterialApp.router`, and `AppTheme`. `lib/app/` is therefore the active composition area, despite the planned `app.dart` file not existing. Evidence: `main`; `MainApp`; `lib/app/bootstrap/startup_route_resolver.dart`; `lib/app/theme/app_theme.dart`.
- **Confirmed — routing and navigation:** `createAppRouter` creates one `GoRouter` with direct `GoRoute` entries. `AppRoutes` provides static path strings; features navigate through `context.go` or `context.push`. The `/main` route hosts a local-index `MainScreen`; it is not a `ShellRoute` or `StatefulShellRoute`. Evidence: `lib/app/router/app_router.dart` (`createAppRouter`); `lib/routes/app_routes.dart` (`AppRoutes`); `lib/app/shell/main_screen.dart` (`_MainScreenState`).
- **Confirmed — state-management coexistence:** Riverpod is active for shared session, theme, Reader persistence, and service wiring (`Provider`, `FutureProvider`, and `AsyncNotifierProvider`). Most ephemeral feature state remains inside `StatefulWidget` instances: login/BMI form state, tool inputs/results, clock ticker, Fox future, and Summertime Saga loading/error/data state. No active GetX, BLoC/Cubit, `ChangeNotifier`, or generated state layer was found. Evidence: `lib/features/auth/application/session_providers.dart`; `lib/app/theme/app_theme_mode_provider.dart`; `lib/features/reader/application/reader_saved_sample_provider.dart`; affected presentation `State` classes.

The router injects the Fox service and Summertime Saga loader into their screens for production/test seams. Screens may also default to direct service construction: `FoxRandomScreen` falls back to `FoxApiService()` and `SmtsHomeScreen` falls back to static `SmtsService.getProgress`. Evidence: `dioProvider`; `foxApiServiceProvider`; `smtsServiceProvider`; `createAppRouter`; `FoxRandomScreen`; `SmtsHomeScreen`.
- **Confirmed — appearance and localization:** `AppTheme` supplies Material 3 light/dark themes using `IwColors` and `IwRadius`; `appThemeModeProvider` persists System/Light/Dark selection with `SharedPreferencesAsync`. Evidence: `lib/app/theme/app_theme.dart`; `lib/app/theme/app_theme_mode_provider.dart`; absent `l10n.yaml` and generated-localization markers.
- **Confirmed — persistence:** `SharedPreferencesAsync` is the only implemented local persistence mechanism. Fox and Summertime Saga each own a feature service, parse a feature model, and translate network/format errors to feature-specific exceptions. No shared interceptor, retry, cache, API-result, or global error abstraction is implemented. Evidence: `lib/core/network/dio_provider.dart`; `FoxApiService`; `SmtsService`; `SmtsProgressModel`.

Fox and Summertime Saga have presentation/application/data/domain separation; Reader has presentation/application/domain; BMI, Clock, and Unit Converter split screen/domain logic; many local tools are presentation-only. Error/loading feedback is feature-local: inline validation in forms, `FutureBuilder` in Fox, and local loading/error/retry state in Summertime Saga. Evidence: feature directories; `BmiScreen`; `FoxRandomScreen`; `SmtsHomeScreen`; `ReaderScreen`.
- **Confirmed — code generation:** no active Dart code-generation convention exists. No `build.yaml`, `l10n.yaml`, `*.g.dart` parts, `build_runner`, Freezed, or json_serializable usage was found.

## Runtime and Data Flows

- **Confirmed — launch:** Android launcher activity → Flutter `main` → `resolveStartupRoute` → `LocalSessionRepository.hasSession` → `/main` when both login flag and non-blank name are stored, otherwise `/login` → `ProviderScope` / `MainApp` / `GoRouter`. Evidence: Android manifest and `MainActivity`; `main`; `resolveStartupRoute`; `LocalSessionRepository.hasSession`.
- **Confirmed — local login/logout:** `LoginScreen` → `localSessionRepositoryProvider` → `LocalSessionRepository.saveSession` → `SharedPreferencesAsync` → `context.go(AppRoutes.main)`; Dashboard logout calls `clearSession` then goes to login. Evidence: `LoginScreen._login`; `DashboardScreen._logout`.
- **Confirmed — shell and feature navigation:** `MainScreen` tab tap → local `_selectedIndex` → selected tab widget; catalog/quick-action tap → `context.push(AppRoutes.<feature>)` → matching `GoRoute` builder. Evidence: `_onItemTapped`; Dashboard/Explore/Tools action handlers; `createAppRouter`.
- **Confirmed — theme:** `SettingsScreen` → `appThemeModeProvider.notifier.setThemeMode` → `AppThemeModeRepository.saveThemeMode` → `SharedPreferencesAsync`; `MainApp` watches the provider and passes the result to `MaterialApp.router`. Evidence: `SettingsScreen`; `AppThemeModeController`; `MainApp.build`.
- **Confirmed — Reader/Library:** Reader entry → `ReaderLastOpenedSampleController.recordSample` → preferences; save/finish/bookmark actions → respective `AsyncNotifier` controller → Reader repository → preferences → `AsyncData` provider state; `LibraryScreen` watches all four provider states to render catalog, continue-reading, saved, and bookmark labels. Evidence: `ReaderScreen`; reader controllers/repositories; `LibraryScreen`.
- **Confirmed — remote features:** route builder → Riverpod service provider → feature service → `createDioClient`/Dio → remote endpoint → parsed model or feature exception → screen-local loading/error/data rendering and Retry/refresh. Fox uses `FutureBuilder`; Summertime Saga uses `_fetchProgress` and an explicit retry state. Evidence: `createAppRouter`; Fox and Summertime Saga providers/services/screens.
- **Confirmed — local tools:** user input → local validation/domain helper or injected random function → `setState` → inline result/error or temporary dialog/history. No local tool flow writes to storage. Evidence: `BmiScreen._calculateBMI`; `UnitConverterScreen._convert`; `RandomPickerScreen._pickOne`; `DecisionWheelScreen` action methods; `ClockScreen` ticker.
